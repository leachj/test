# 📋 Task Manager

A full-stack task management application with a React (TypeScript) frontend and a Rust (Axum) backend. Create, view, update, complete, and delete tasks through a small REST API backed by an in-memory store.

## ✨ Features

- Create tasks with a title and optional description
- List all tasks and fetch a single task by id
- Update a task's title, description, or completion state
- Delete tasks
- Full CI on every push and pull request to `main`

## 🧰 Tech Stack

| Layer     | Technologies                                             |
|-----------|----------------------------------------------------------|
| Frontend  | React 18, TypeScript, Vite, Vitest, Testing Library      |
| Backend   | Rust, Axum 0.7, Tokio, Serde, `uuid`, `chrono`, tower-http |

- [Node.js](https://nodejs.org/) 18+ and `npm`

## 🚀 Getting Started

### 🦀 Backend

```bash
cd backend
cargo run           # Start dev server on http://localhost:3001
cargo build --release  # Production build
cargo test          # Run tests
cargo clippy        # Lint
cargo fmt           # Format
```

The backend listens on port `3001` by default. Set the `PORT` environment
variable to override it:

```bash
PORT=8080 cargo run
```

### ⚛️ Frontend

```bash
cd frontend
npm install
npm run dev        # Start Vite dev server on http://localhost:3000
npm run build      # Production build → dist/
npm test           # Run Vitest tests
npm run lint       # ESLint
```

> The frontend dev server proxies `/api` requests to the backend at `http://localhost:3001`.

## 🔌 API Endpoints

Base URL: `http://localhost:3001`

| Method | Path              | Description        | Success Status |
|--------|-------------------|--------------------|----------------|
| GET    | `/health`         | Health check       | `200 OK`       |
| GET    | `/api/tasks`      | List all tasks     | `200 OK`       |
| POST   | `/api/tasks`      | Create a task      | `201 Created`  |
| GET    | `/api/tasks/:id`  | Get a single task  | `200 OK`       |
| PATCH  | `/api/tasks/:id`  | Update a task      | `200 OK`       |
| DELETE | `/api/tasks/:id`  | Delete a task      | `204 No Content` |

### 🧱 Task Model

```jsonc
{
  "id": "1f9d…",          // UUID v4, generated by the server
  "title": "Buy milk",    // required, trimmed
  "description": "2%",    // optional, trimmed, defaults to ""
  "completed": false,     // defaults to false on create
  "createdAt": "2024-01-01T12:00:00+00:00" // RFC 3339 timestamp
}
```

`POST /api/tasks` accepts `{ "title": string, "description"?: string }` and
requires a non-empty `title`. `PATCH /api/tasks/:id` accepts any subset of
`{ "title", "description", "completed" }`; omitted fields are left unchanged.

### 📥 Example Requests

```bash
# Create a task
curl -X POST http://localhost:3001/api/tasks \
  -H "Content-Type: application/json" \
  -d '{"title":"Write docs","description":"Expand the README"}'

# Mark it complete
curl -X PATCH http://localhost:3001/api/tasks/<id> \
  -H "Content-Type: application/json" \
  -d '{"completed":true}'

# Delete it
curl -X DELETE http://localhost:3001/api/tasks/<id>
```

### ⚠️ Error Responses

Errors are returned as JSON with the failing HTTP status code:

```jsonc
{
  "error": {
    "message": "Task not found",
    "statusCode": 404
  }
}
```

A missing or empty `title` on create yields `400 Bad Request`; an unknown id on
get, update, or delete yields `404 Not Found`.

> ⚠️ **Note:** Tasks are stored in memory, so all data is lost when the backend
> process restarts.
